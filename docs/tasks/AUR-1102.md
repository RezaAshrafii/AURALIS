## Current Architecture

The implementation evidence currently establishes:

- Bun local runtime.
- `server.mjs` is the local HTTP server.
- Local bind is `127.0.0.1:47832`.
- Persistence uses SQLite WAL.
- Current schema version is 7.
- Frontend is the vendored React SPA under `app/`.
- Realtime behavior currently uses HTTP polling over the persisted `event_log`.
- WebSocket and SSE are NOT currently implemented.
- Provider/API credentials are supplied at runtime, retained in memory, and must not be persisted or logged.
- `core/*.mjs` contains pure domain logic.
- `native/core` is currently a Rust contract/scaffold, not the production WASAPI implementation.

## Contract Scope

The authoritative CURRENT contract must capture, from implementation evidence:

1. Current `/v1` HTTP routes.
2. HTTP method for each route where determinable.
3. Dynamic route parameters where determinable.
4. Current `event_log` event vocabulary.
5. Important DTO / response / domain shapes crossing server/UI boundaries.
6. Current schema version relevant to consumers.
7. Current realtime transport semantics.
8. Authentication/token assumptions relevant to consumers.

Do not invent fields, routes, methods, events, or semantics.

## Current vs Target

CURRENT and TARGET/FUTURE definitions must be explicitly separated.

CURRENT means implemented by the v0.10.12 runtime.

TARGET/FUTURE may document intended later capabilities such as:

- WebSocket delivery
- `audio.level`
- `segment.started`
- `transcript.partial`
- `answer.partial`
- `gap.detected`
- `device.changed`
- production Rust WASAPI audio core
- VAD
- streaming ASR

A TARGET/FUTURE capability must never be represented or tested as CURRENT.

Do not implement TARGET/FUTURE behavior in AUR-1102.
