# پرامپت اجرایی AURALIS v0.19.0 — Monetization Beta

## دستور به مدل اجرایی

قرارداد مادر و تمام اسناد تا v0.18 را بخوان. baseline اجباری v0.18.0 با Cloud/Identity/Tenancy/Usage واقعی است. این نسخه monetization را server-authoritative می‌کند. paywall نمایشی، entitlement داخل frontend، mock payment در production یا double-count usage شکست بحرانی است.

## 1. نتیجهٔ محصول

کاربر بتواند Plan خود را ببیند، upgrade/downgrade/cancel کند، مصرف و quota را شفاف ببیند و در Android یا channel پرداخت پیکربندی‌شده خرید انجام دهد. Workspace/Organization طبق entitlement رفتار کند و failure/refund/grace/retry بدون از دست‌دادن داده مدیریت شود.

Plan families:

```text
FREE -> PRO -> BUSINESS
```

Plan نام بازاری است؛ رفتار محصول فقط از Entitlementهای versioned و server-side می‌آید.

## 2. Scope

### داخل Scope

- product/price/plan catalog؛
- subscription lifecycle؛
- provider-neutral Billing Port؛
- حداقل یک real beta adapter در sandbox/internal track؛
- Android purchase verification server-side؛
- webhook/in-app purchase event ledger؛
- entitlement resolution؛
- metered usage aggregation و quota enforcement؛
- trial/grace/cancel/refund/restore purchase؛
- Free/Pro/Business product UX؛
- Business seat/member entitlement؛
- admin/support-safe billing diagnostics؛
- revenue/activation/churn beta analytics بدون PII leakage.

### خارج از Scope

- تغییر بزرگ Core/Memory/Sync؛
- crypto payment؛
- ad network؛
- marketplace/reseller complex billing؛
- tax/legal invoice claim بدون provider/regional compliance؛
- «Unlimited» بدون fair-use policy؛
- store public commercial launch نهایی؛ آن متعلق به v1.0 است.

## 3. تصمیم‌های Product که باید config-driven باشند

این مقادیر را در seed/config versioned بگذار، نه شرط hard-coded:

- quota هر Plan؛
- enabled model keys؛
- retention/storage؛
- تعداد Workspace/Member/Device؛
- export/advanced search/cloud sync access؛
- trial duration؛
- grace duration؛
- price/currency/region/channel؛
- feature rollout.

قیمت نهایی، tax wording و provider production credential تصمیم تجاری/منطقه‌ای است. اگر در ورودی تعیین نشده، infrastructure و sandbox را کامل کن و production activation را `BLOCKED_BY_PRODUCT_DECISION` ثبت کن؛ مقدار ساختگی منتشر نکن.

## 4. معماری Billing Context

```text
Billing Provider Event / Verified Purchase
  -> Immutable Billing Event Ledger
  -> Subscription State Machine
  -> Entitlement Snapshot
  -> Quota Resolver
  -> Application Authorization
  -> Usage/Reconciliation/Audit
```

Billing Provider هرگز مستقیماً Workspace feature را toggle نمی‌کند. Adapter event canonical می‌سازد؛ Domain state machine آن را اعمال می‌کند؛ Entitlement resolver snapshot می‌دهد.

## 5. Schema v0.19

### 5.1 Catalog

`billing_products`

- `id`, `code FREE|PRO|BUSINESS`؛
- `name`, `status ACTIVE|INACTIVE`؛
- `catalog_version`, timestamps.

`billing_prices`

- `id`, `product_id`؛
- `billing_period MONTH|YEAR|NONE`؛
- `amount_minor`, `currency`؛
- `region`, `channel WEB|GOOGLE_PLAY|BAZAAR|MYKET|MANUAL_BETA`؛
- `external_price_id`؛
- `tax_behavior` enum؛
- `effective_from`, `effective_until`, `status`؛
- unique active external ID/channel.

`entitlement_definitions`

- `key` PK مثل `memory.max_items`, `models.allowed`, `team.max_members`؛
- `value_type BOOLEAN|INTEGER|STRING_SET|DURATION|BYTES`؛
- `description`, `enforcement_mode HARD|SOFT|OBSERVE`.

`product_entitlements`

- `product_id`, `entitlement_key`, `value_json`, `catalog_version`؛
- schema/check validation؛
- PK مرکب.

### 5.2 Customer و Subscription

Billing owner یکی از `USER|ORGANIZATION` است. Business معمولاً Organization owner دارد.

`billing_customers`

- `id`, `owner_type`, `owner_id`؛
- `provider`, `external_customer_id` nullable؛
- `status`, timestamps؛
- no full payment instrument data.

`subscriptions`

- `id`, `billing_customer_id`, `product_id`, `price_id`؛
- `provider`, `external_subscription_id`؛
- `state INCOMPLETE|TRIALING|ACTIVE|PAST_DUE|GRACE|PAUSED|CANCEL_AT_PERIOD_END|CANCELLED|EXPIRED|REFUNDED`؛
- `current_period_start/end`, `trial_end`, `grace_end`؛
- `cancel_at_period_end`, `cancelled_at`؛
- `provider_revision`/last event time؛
- `revision`, timestamps؛
- invariant یک effective subscription per billing owner/channel طبق policy.

`subscription_events`

- append-only state transition با from/to/reason/provider event ID/actor/timestamp.

### 5.3 Provider event ledger

`billing_provider_events`

- `id`, `provider`, `external_event_id` UNIQUE؛
- `event_type`, `received_at`, `verified_at`؛
- `signature_valid`؛
- `payload_ciphertext_or_reference` طبق retention؛ raw sensitive payload در log ممنوع؛
- `payload_hash`؛
- `processing_state RECEIVED|VERIFIED|APPLIED|IGNORED|FAILED`؛
- `attempt`, `error_code`, timestamps.

Event ordering خارج از ترتیب را با provider effective time/revision و state machine مدیریت کن. Event duplicate پاسخ موفق idempotent می‌گیرد.

### 5.4 Entitlement snapshot

`entitlement_snapshots`

- `id`, `owner_type`, `owner_id`؛
- `catalog_version`, `subscription_revision`؛
- `entitlements_json` validated؛
- `effective_from`, `effective_until`؛
- `source FREE_DEFAULT|SUBSCRIPTION|TRIAL|GRACE|MANUAL_SUPPORT`؛
- `fingerprint`, `created_at`؛
- immutable.

Current snapshot pointer یا deterministic latest query با transaction-safe update. Cache correctness source نیست.

`manual_entitlement_grants`

- support/admin only؛ reason، expiry، actor، audit؛
- permanent hidden bypass ممنوع.

### 5.5 Usage و quota

`usage_events` v0.18 authoritative append-only باقی می‌ماند.

`usage_aggregates`

- owner/workspace/metric/window start/end؛
- quantity integer؛
- last_usage_event_sequence؛
- revision؛
- unique window key.

`quota_reservations`

- `id`, owner/workspace/metric؛
- `quantity`, `state RESERVED|COMMITTED|RELEASED|EXPIRED`؛
- idempotency key، job ID، expiry؛
- برای AI/audio requestهای پرهزینه از check-then-race جلوگیری می‌کند.

`quota_decisions`

- allow/deny/soft warning؛ entitlement snapshot ID، aggregate، requested quantity، reason، correlation، timestamp؛
- content ندارد.

## 6. Subscription state machine

تمام transitionهای مجاز را pure/domain test کن. نمونه:

```text
INCOMPLETE -> TRIALING|ACTIVE|CANCELLED
TRIALING -> ACTIVE|EXPIRED|CANCELLED
ACTIVE -> PAST_DUE|CANCEL_AT_PERIOD_END|CANCELLED|REFUNDED
PAST_DUE -> ACTIVE|GRACE|CANCELLED
GRACE -> ACTIVE|EXPIRED|CANCELLED
CANCEL_AT_PERIOD_END -> ACTIVE|EXPIRED
```

Transition نامعتبر reject + audit. Provider event قدیمی نباید state جدیدتر را عقب ببرد. Refund/cancel دادهٔ کاربر را حذف نمی‌کند؛ فقط entitlement آینده طبق policy تغییر می‌کند.

## 7. Billing Provider Port

Interface حداقل:

- `createCheckoutSession` برای channel پشتیبان؛
- `verifyPurchase` برای Store purchase token؛
- `parseAndVerifyWebhook`؛
- `fetchSubscriptionStatus`؛
- `cancelSubscription`؛
- `restorePurchases`/reconcile؛
- `mapExternalProduct`.

Adapterها:

- `FakeBillingProvider` فقط tests؛ production guard باید آن را رد کند.
- حداقل یک `RealBetaBillingProvider` برای channel انتخاب‌شده با sandbox credential؛
- Android Google Play adapter در صورت انتخاب channel: purchase token از client به server، verification server-side، acknowledgement policy، Real-time developer notification/webhook؛ client response به‌تنهایی entitlement نمی‌دهد.
- Bazaar/Myket/Web adapterها پشت همین Port؛ اگر provider/credential انتخاب نشده contract + disabled config کافی است ولی قابلیت paid آن channel claim نشود.

Secret در server secret manager. Webhook signature/issuer/audience/package/product binding و replay protection اجباری.

## 8. Entitlement Resolution

یک `EntitlementService` مرکزی و server-side بساز:

- `resolve(owner, workspace)`؛
- `checkBoolean(key)`؛
- `checkLimit(key,current,requested)`؛
- `allowedSet(key)`؛
- `reserveQuota`, `commitQuota`, `releaseQuota`؛
- snapshot ID را به decision/audit برگرداند.

تمام featureهای پولی API از این service استفاده کنند. UI فقط `capabilities/limits/usage` redacted response را render کند.

حداقل keyها:

```text
workspace.max_count
team.max_members
conversation.monthly_count
audio.monthly_seconds
storage.max_bytes
memory.max_items
documents.enabled
export.enabled
advanced_search.enabled
cloud_sync.enabled
models.allowed
devices.max_count
retention.max_days
```

Valueهای واقعی seed config هستند. `-1=unlimited` مبهم ممنوع؛ از union صریح `{kind:"UNBOUNDED"}` فقط با fair-use policy استفاده شود.

## 9. Quota enforcement semantics

- read existing data بعد downgrade معمولاً مجاز؛ create/compute جدید محدود طبق policy؛
- user هرگز به‌علت quota از Export/Delete/Privacy controls محروم نشود؛
- capture آفلاین اگر quota نامشخص است local را از دست ندهد؛ state `PENDING_QUOTA_CHECK` و sync policy مشخص؛
- AI request قبل از provider call reservation؛ success commit؛ failure release؛ timeout reconciliation؛
- usage event exactly-once logical با idempotency؛
- hard/soft/observe mode per entitlement؛
- grace banner و تاریخ دقیق؛
- quota reset timezone/window server-defined و شفاف.

## 16. Acceptance scenarios

1. New user -> Free snapshot deterministic.
2. Pro sandbox purchase -> verified event -> ACTIVE -> new entitlement snapshot -> UI unlock؛ duplicate notification بدون duplicate subscription.
3. forged purchase -> no entitlement.
4. payment failure -> PAST_DUE/GRACE طبق policy؛ data readable، banners correct.
5. cancel at period end -> access تا end، سپس Free؛ no data deletion.
6. refund/revocation -> state/effective entitlement correct و audit.
7. AI quota concurrent requests -> reservations limit را تجاوز نمی‌کنند؛ failure release.
8. offline Android capture near quota -> raw محفوظ، sync state شفاف، server decision deterministic.
9. Business seats -> invite over limit reject، removal release.
10. catalog price change -> subscription historical price preserved؛ new checkout new price.
11. provider outage -> local/Core work، checkout unavailable، state جعلی نشود.
12. entitlement service cache flush -> canonical snapshot recovery.
