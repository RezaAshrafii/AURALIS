# پرامپت اجرایی AURALIS v1.0.0 — Commercial Release

## دستور به مدل اجرایی

قرارداد مادر و تمام اسناد v0.15 تا v0.19 را کامل بخوان. baseline فقط v0.19.0 beta با evidence واقعی است. v1.0 نسخهٔ افزودن feature جدید نیست؛ نسخهٔ حذف ابهام، کاهش ریسک، تکمیل عملیات و اثبات آمادگی فروش است. هر feature ناقص یا آزمایشی یا باید کامل gate شود، یا پشت flag غیرفعال و از marketing حذف شود.

## 1. تعریف Done تجاری

محصولی قابل فروش است که:

- کاربر بداند چه ارزشی می‌خرد؛
- مسیر onboarding تا اولین نتیجه بدون کمک مهندس کامل شود؛
- داده در crash/network/provider failure گم نشود؛
- Backup/Restore/Delete/Export واقعی باشد؛
- امنیت و privacy ممیزی شده باشد؛
- subscription و support قابل اتکا باشد؛
- Windows و Android artifact امضاشده، قابل rollback و قابل توزیع باشند؛
- تیم بداند در incident چه کند؛
- claimهای سایت/store دقیقاً با capability فعال یکسان باشند.

نمونهٔ truthfulness:

- model names marketing core value نیستند.

## 5. Quality gates کمی

این targetها حداقل داخلی‌اند و باید با environment/evidence گزارش شوند:

### Data correctness

- canonical data loss: صفر در crash/restart/kill/network fault suite؛
- duplicate logical mutation/job/charge: صفر در retry suite؛
- unexplained audio loss: صفر؛ loss واقعی Gap دارد؛
- cross-tenant leak: صفر؛
- migration row/ID/provenance mismatch: صفر؛
- backup restore integrity hash mismatch: صفر.

### Reliability

- Cloud API monthly availability target حداقل 99.9%؛
- Android crash-free sessions target حداقل 99.5% در RC cohort؛
- Android ANR target حداکثر 0.5%؛
- job success after bounded retry target حداقل 99.5% برای dependency سالم؛
- sync convergence success 100% روی deterministic chaos suite؛
- Windows 120-minute mic+loopback soak با queue drop صفر یا Gap صریح و gate مطابق hardware plan.

### Latency

Budget دقیق را از v0.18/v0.19 حفظ یا بهتر کن. حداقل report:

- API p50/p95/p99؛
- sync first-page و full convergence؛
- upload throughput/resume؛
- time from finalized audio to transcript؛
- dashboard/search/action/memory query؛
- entitlement check؛
- Android cold/warm start و UI frame metrics.

هیچ عددی بدون sample size/environment/time window منتشر نشود.

### Recovery

- RPO target حداکثر 15 دقیقه؛
- RTO target حداکثر 4 ساعت؛
- restore drill کامل قبل از launch و سپس schedule؛
- rollback application و forward-fix migration rehearsal.

اگر business target متفاوت است، ADR با تأیید Product لازم؛ target را پنهانی کاهش نده.

## 7. Security release gate

### استاندارد و scope

- Web/API بر مبنای OWASP ASVS Level 2 control mapping؛
- Android بر مبنای OWASP MASVS relevant controls؛
- threat model نهایی برای Auth/Tenant/Sync/Blob/AI/Billing/Push/Installer/Update؛
- independent security review یا pentest برای internet-facing scope؛
- no open Critical/High vulnerability؛ Medium فقط با owner/deadline/accepted risk.

### Automated/manual checks

- SAST، dependency، container، IaC، secret، SBOM، license scan؛
- auth token/key rotation/revocation؛
- RLS/IDOR/role escalation؛
- upload/path traversal/MIME/hash/malware policy؛
- SSRF/deserialization/prompt injection/data exfiltration؛
- billing webhook/purchase replay/forgery؛
- Android exported components/deep links/backup/Keystore/logging؛
- Windows code signing/installer/update integrity؛
- admin/support least privilege و audit؛
- rate limit/abuse/cost amplification.

Security exception بدون signed risk record release blocker است.

- install/uninstall/repair/update/rollback؛
- user data preserve/remove choice؛
- firewall/loopback behavior؛
- crash logs redacted؛
- clean VM test.

### Android

- capability matrix و marketing parity کامل؛
- no critical/high bugs/security issues؛
- quantitative quality gates evidence؛
- platform artifacts signed/reproducible/SBOM/checksum؛
- migration/rollback/backup/restore proven؛
- billing/store sandbox و channel production checks؛
- privacy/legal/support/docs/onboarding آماده؛
- observability/on-call/runbooks فعال؛
