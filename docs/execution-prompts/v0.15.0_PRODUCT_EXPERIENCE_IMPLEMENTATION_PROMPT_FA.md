# پرامپت اجرایی AURALIS v0.15.0 — Product Experience Layer

## دستور به مدل اجرایی

تو بازوی اجرای کد هستی، نه مالک معماری. ابتدا فایل `00_AURALIS_MASTER_ARCHITECTURE_AND_EXECUTION_CONTRACT_FA.md` را کامل بخوان و سپس این سند را اجرا کن. baseline اجباری v0.14.1 است. خروجی باید کد production، migration، تست، مستندات و evidence باشد؛ طرح، mockup یا pseudo-code به‌تنهایی پذیرفته نیست.

## 1. نتیجهٔ محصول

کاربر بعد از این نسخه نباید با «یک Session مهندسی» روبه‌رو باشد. تجربه باید این زنجیره را واقعاً پیاده کند:

```text
Goal -> Workspace -> Project/People/Documents -> Conversation -> Understanding -> Action
```

یک کاربر محلی باید بتواند Workspace بسازد، Project و Person تعریف کند، Conversation را در Project شروع کند، Transcript/Decision/Task/Commitment را جدا ببیند، Task را تأیید/ویرایش/ببندد و همه‌چیز را جست‌وجو کند.

## 2. Scope قطعی

### داخل Scope

- Workspace، Project، People، Documents، Conversations و Tasks واقعی؛
- Conversation Hub سه‌لایهٔ Audio/Transcript/Understanding؛
- extraction ساختاریافتهٔ Decision/Task/Commitment با provenance؛
- Action Center؛
- Dashboard، Search، Global Command، keyboard shortcut؛
- dark/light کامل، responsive و accessibility؛
- migration دادهٔ v0.14.1 بدون از دست‌دادن Session/Turn/Source؛
- شکستن تدریجی `server.mjs` به module/repository/service/route بدون بازنویسی Native Core.

### خارج از Scope

- حافظهٔ یادگیرنده یا شناخت دائمی کاربر؛
- account/cloud/sync/team/organization؛
- billing/subscription؛
- CRM/Meeting/Assistant عمودی؛
- Android؛
- neural VAD یا تغییر capture pipeline؛
- اعلان push یا اتصال Calendar/Email.

صفحهٔ Memories می‌تواند فقط توضیح صادقانهٔ «در v0.16 فعال می‌شود» داشته باشد. جدول یا دادهٔ memory جعلی نساز.

## 3. Baseline gate پیش از تغییر

اجرا و ثبت کن:

```text
npm ci
npm run verify
npm run intelligence:benchmark
```

روی Windows همچنین:

```text
BUILD-V014-PRODUCT-BRIDGE.cmd
RUN-V014-PRODUCT-BRIDGE-GATE.cmd
```

اگر Windows در دسترس نیست، `NOT_RUN` ثبت کن؛ هرگز PASS جعل نکن. v0.15 حق تغییر کد `native/core/audio` را ندارد مگر رفع regression اثبات‌شده و تأییدشده.

## 4. تصمیم معماری

محصول همچنان local-first modular monolith است:

```text
apps/web
  -> application API
     -> workspace / conversation / understanding / action services
        -> domain modules
           -> repository ports
              -> SQLite adapters
```

ساختار هدف حداقل:

```text
application/
  workspace/
  conversation/
  understanding/
  action/
  search/
adapters/
  sqlite/
  ai/
api/
  routes/
core/ or domain/
packages/contracts/
apps/web/
```

`server.mjs` فقط composition root، lifecycle و route mounting می‌ماند. SQL جدید، validation دامنه‌ای و prompt جدید نباید inline در آن اضافه شود. استخراج legacy باید با contract test انجام شود؛ big-bang rewrite ممنوع است.

## 5. مدل دامنه و Schema

Application schema را از 9 به 10 با migrationهای append-only ارتقا بده.

### 5.1 Local Profile و Workspace

`local_profiles`

- `id` PK؛
- `display_name`؛
- `locale` default `fa-IR`؛
- `timezone` IANA؛
- `created_at`, `updated_at`.

`workspaces`

- `id` PK؛
- `local_profile_id` FK؛
- `name`؛
- `description`؛
- `status ACTIVE|ARCHIVED`؛
- `revision` integer optimistic concurrency؛
- timestamps.

در migration یک profile و Workspace پیش‌فرض idempotent بساز. تمام دادهٔ قبلی به همان Workspace متصل شود.

### 5.2 Projects و People

`projects`

- `id`, `workspace_id`, `name`, `description`؛
- `status ACTIVE|ON_HOLD|COMPLETED|ARCHIVED`؛
- `color_token` فقط از allowlist؛
- `revision`, timestamps؛
- unique normalized active name per Workspace.

`people`

- `id`, `workspace_id`, `display_name`؛
- `organization_name`, `role_title`, `email`, `phone` nullable؛
- `notes` user-authored only؛
- `status ACTIVE|ARCHIVED`؛
- `revision`, timestamps.

`project_people(project_id, person_id, relationship_label, created_at)` با PK مرکب.

### 5.3 Conversations

جدول legacy `sessions` مرجع capture باقی می‌ماند. روی آن Product semantics سوار نکن.

`conversations`

- `id` PK؛
- `workspace_id` FK؛
- `project_id` nullable FK؛
- `capture_session_id` nullable UNIQUE FK به `sessions`؛
- `title`؛
- `goal`؛
- `kind GENERAL|CALL|MEETING|INTERVIEW|NOTE`؛
- `state DRAFT|STARTING|LIVE|PROCESSING|READY|FAILED|ARCHIVED`؛
- `started_at`, `ended_at`, `created_at`, `updated_at`؛
- `revision`.

`conversation_participants`

- `conversation_id`, `person_id`؛
- `participant_role`؛
- `speaker_channel_id` nullable؛
- PK مرکب.

`conversation_documents`

- `conversation_id`, `document_id`؛
- `purpose CONTEXT|AGENDA|REFERENCE|OUTPUT`؛
- PK مرکب.

تمام Sessionهای قبلی idempotent به Conversation تبدیل شوند. ID Conversation مستقل باشد و mapping پایدار بماند.

### 5.4 Understanding

`understanding_runs`

- `id`, `conversation_id`؛
- `input_fingerprint`؛
- `prompt_version`, `provider`, `provider_model`؛
- `state QUEUED|RUNNING|COMPLETED|FAILED|SUPERSEDED`؛
- `attempt`, `error_code`, timestamps؛
- UNIQUE `(conversation_id,input_fingerprint,prompt_version)`.

`insight_items`

- `id`, `workspace_id`, `conversation_id`, `run_id`؛
- `type DECISION|TASK|COMMITMENT|OPEN_QUESTION|RISK`؛
- `title`, `body`؛
- `status SUGGESTED|CONFIRMED|DISMISSED|SUPERSEDED`؛
- `confidence` check `[0,1]`؛
- `assignee_person_id` nullable؛
- `due_at_utc`, `due_timezone`, `due_original_text`, `due_parse_confidence` nullable؛
- `fingerprint`؛
- `created_by AI|USER`؛
- `revision`, timestamps؛
- UNIQUE canonical active fingerprint per Conversation/type.

`insight_evidence`

- `insight_id`؛
- `turn_id` nullable؛
- `segment_id` nullable؛
- `document_chunk_id` nullable؛
- `exact_quote`؛
- `start_offset`, `end_offset` nullable؛
- حداقل یکی از مراجع evidence با CHECK/Application invariant الزامی است.

AI item بدون evidence معتبر canonical نمی‌شود. confidence پایین‌تر از threshold تنظیم‌شده در UI فقط با برچسب «نیاز به بررسی» نمایش داده شود.

### 5.5 Tasks

`tasks`

- `id`, `workspace_id`, `project_id` nullable، `conversation_id` nullable؛
- `source_insight_id` nullable UNIQUE؛
- `title`, `description`؛
- `state SUGGESTED|TODO|IN_PROGRESS|DONE|CANCELLED`؛
- `priority NONE|LOW|MEDIUM|HIGH`؛
- `assignee_person_id` nullable؛
- deadline fields همان قرارداد بالا؛
- `completed_at`, `revision`, timestamps.

`task_events`

- append-only تغییر status/assignee/deadline؛
- `id`, `task_id`, `event_type`, `actor`, `from_json`, `to_json`, `occurred_at`.

تأیید Insight نوع TASK باید در یک transaction Task بسازد و Insight را CONFIRMED کند. retry نباید Task تکراری بسازد.

### 5.6 Search

یک FTS projection versioned برای Project/Person/Document/Conversation/Transcript final/Insight/Task بساز. projection باید از canonical record rebuild شود و delete/archive را رعایت کند. raw audio، secret، error detail و superseded transcript در index عمومی قرار نگیرد.

## 6. Understanding pipeline

ورودی extraction فقط Turnهای final و user-confirmed context است. خروجی Provider دقیقاً با JSON Schema زیر validate شود:

```json
{
  "schemaVersion": 1,
  "summary": "string",
  "items": [
    {
      "type": "DECISION|TASK|COMMITMENT|OPEN_QUESTION|RISK",
      "title": "string",
      "body": "string",
      "confidence": 0.0,
      "assigneeText": "string|null",
      "dueText": "string|null",
      "evidence": [{"turnId":"id","quote":"exact quote"}]
    }
  ]
}
```

قواعد:

- exact quote باید واقعاً داخل Turn مجاز باشد؛ در غیر این صورت item رد و audit شود.
- assignee فقط با match بدون ابهام به Person وصل شود؛ در غیر این صورت null + متن پیشنهادی.
- deadline parser deterministic و timezone-aware است؛ تاریخ مبهم قطعی نشود.
- extraction با input fingerprint idempotent است.
- rerun نتیجهٔ قبلی را حذف نمی‌کند؛ run قبلی SUPERSEDED و lineage حفظ می‌شود.
- summary با transcript canonical یکی نیست و باید برچسب AI-generated داشته باشد.

## 10. Compatibility و Migration

1. قبل از migration backup قابل بازگشت بساز.
2. default local profile/workspace idempotent بساز.
3. Sourceهای موجود را به Workspace وصل کن؛ اگر افزودن FK مستقیم پرریسک است link table با backfill بساز.
4. هر Session موجود را به یک Conversation با title deterministic و capture mapping تبدیل کن.
5. Turn/Segment/Answer/Citation IDها تغییر نکنند.
6. API legacy با adapter به Conversation جدید mapping شود.
7. migration دوبار اجراشدن و restart وسط backfill را تحمل کند.
8. rollback app باید DB جدید را بدون corruption حداقل read-only تشخیص دهد؛ downgrade خاموش ممنوع.

## 11. Security و Privacy delta

- playback endpoint path خام filesystem را افشا نکند؛ Range و ownership را validate کند.
- search snippets HTML-escape شوند.
- Person contact fields در diagnostics/log حذف شوند.
- AI prompt فقط Turnهای همان Workspace/Conversation را بگیرد.
- file upload همان size/MIME/hash policy v0.14 را حفظ کند.
- state mutation token و local trust boundary regression نداشته باشد.

## 12. تست‌های پذیرش اجباری

### Workspace flow

1. clean install -> default Workspace؛
2. ساخت Project و Person؛
3. شروع Conversation داخل Project با Person؛
4. capture readiness واقعی؛
5. Transcript final؛
6. extraction دارای Decision/Task/Commitment با evidence؛
7. تأیید Task فقط یک Task می‌سازد؛
8. Task در Dashboard، Action Center و Search دیده می‌شود.

### Migration

- fixture واقعی v0.14.1 با Session/Source/Turn/Answer migrate شود؛
- count و IDهای canonical قبل/بعد برابر؛
- Conversation wrapper درست؛
- migration rerun no-op.

### Failure

- Provider unavailable: Conversation/Transcript حفظ، understanding FAILED قابل retry؛
- quote جعلی: Insight رد؛
- deadline مبهم: due_at null؛
- capture protocol timeout: Conversation LIVE نشود؛
- concurrent Task update: 409 conflict و data loss صفر؛
- archive Project: Conversation/Task حذف نشوند.

### Performance budget روی fixture مشخص

- Dashboard local p95 زیر 300ms با 10k Task و 5k Conversation؛
- global search p95 زیر 500ms با 100k projection row؛
- Conversation Hub initial load pagination داشته باشد و کل Transcript را یکجا نکشد.

## 13. Release gate و Definition of Done

نسخه فقط وقتی Done است که:

- تمام baseline gateها سبز باشند؛
- full regression zero failure؛
- schema 10 migration clean + v0.14.1 fixture pass؛
- UI مسیر کامل Workspace تا Action را بدون manual DB/API اجرا کند؛
- هیچ صفحه یا button جعلی/مرده نباشد؛
- capture/ASR v0.14.1 regression نداشته باشد؛
- dark/light/responsive/a11y gate evidence موجود باشد؛
- قابلیت Memory/Cloud/Billing صادقانه non-capability ثبت شود؛
- artifact با version 0.15.0 و SHA-256 تولید شود.
