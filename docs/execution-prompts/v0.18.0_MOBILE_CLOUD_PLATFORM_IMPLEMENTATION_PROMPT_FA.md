# پرامپت اجرایی AURALIS v0.18.0 — Mobile + Cloud Platform

## دستور به مدل اجرایی

قرارداد مادر و تمام پرامپت‌های v0.15 تا v0.17 را بخوان. baseline فقط v0.17.0 تأییدشده است. این نسخه مرز trust، persistence و deployment را عوض می‌کند؛ قبل از کدنویسی ADRهای Cloud/Tenancy/Auth/Sync/Audio Upload را بنویس. با این حال تا Stop Condition واقعی کار را متوقف نکن.

## 1. نتیجهٔ محصول

یک کاربر باید بتواند در Android وارد حساب شود، Workspaceهای مجازش را ببیند، مکالمهٔ میکروفونی را حتی آفلاین ثبت کند، بعداً sync/upload کند، Transcript/Understanding/Task/Memory را روی Android و Desktop یکسان ببیند، اعلان موعد دریافت کند و در برابر قطع شبکه یا اجرای تکراری دادهٔ تکراری/گم‌شده نداشته باشد.

## 2. Scope

### داخل Scope

- Cloud modular monolith: stateless API + background Worker؛
- PostgreSQL، object storage سازگار با S3 API، migration و backup؛
- OIDC/OAuth 2.1-style authorization code + PKCE برای client؛
- Users، Organizations، Memberships، Roles، Devices؛
- multi-tenant Workspace؛
- sync protocol برای metadata و resumable audio blobs؛
- Android Kotlin/Compose با offline queue؛
- Desktop sync adapter برای محصول محلی موجود؛
- model gateway، AI jobs، usage ledger؛
- push notification Android؛
- observability، audit، retention، export/delete account workflow؛
- import کنترل‌شدهٔ local v0.17 data.

### خارج از Scope

- billing enforcement و plan paywall کامل؛
- iOS؛
- browser system-audio capture؛
- Android system/other-app audio capture؛ فقط microphone صادقانه؛
- E2EE claim؛ server برای ASR/AI به content نیاز دارد؛
- microservices، Kafka و Kubernetes اجباری؛
- autonomous outbound email/call؛
- store commercial launch نهایی.

## 4. Identity و Tenancy

### 4.1 Authentication

- Cloud API access token امضاشده از OIDC issuer معتبر را validate می‌کند: issuer، audience، expiry، nonce/state/PKCE در client؛
- Android از system browser و Authorization Code + PKCE استفاده می‌کند؛ WebView credential capture ممنوع؛
- refresh token فقط در Android Keystore-backed secure storage؛ Desktop در OS credential vault؛
- token در log/analytics/URL/localStorage ممنوع؛
- production OIDC issuer config یک release dependency است؛ dev fake فقط test/dev و fail-closed در production.

### 4.2 Schema

`users`

- `id`, `status ACTIVE|SUSPENDED|DELETION_PENDING|DELETED`؛
- `display_name`, `locale`, `timezone`؛
- timestamps.

`user_identities`

- `id`, `user_id`, `issuer`, `subject`؛
- unique `(issuer,subject)`؛
- email فقط اگر verified claim و با policy؛
- raw token ذخیره نشود.

`organizations`

- `id`, `name`, `status`, `revision`, timestamps.

`memberships`

- `organization_id`, `user_id` PK؛
- `role OWNER|ADMIN|MEMBER|VIEWER`؛
- `status INVITED|ACTIVE|SUSPENDED|REMOVED`؛
- invitation metadata؛
- حداقل یک OWNER invariant.

`cloud_workspaces`

- `id`, `organization_id`, `name`, `product_profile`, `status`, `revision`, timestamps.

تمام tableهای tenant-owned `organization_id` و `workspace_id` مناسب دارند. authorization query scope + PostgreSQL RLS defense-in-depth؛ connection context اشتباه نباید data expose کند. test cross-tenant اجباری.

### 4.3 Role matrix

یک matrix versioned تعریف کن. حداقل:

- OWNER: org/settings/membership/delete؛
- ADMIN: workspace/member management بدون حذف owner؛
- MEMBER: create/update product data؛
- VIEWER: read/export فقط در صورت policy، بدون capture write.

UI permission را server response مصرف می‌کند؛ server هر mutation را enforce می‌کند.

## 5. Cloud persistence و source-of-truth

PostgreSQL schema نسخهٔ 1 از مدل v0.17 ساخته شود، نه dump مستقیم SQLite. mapping IDs حفظ شود. هر record:

- `organization_id`, `workspace_id`؛
- `revision`؛
- `created_at`, `updated_at`؛
- `deleted_at` tombstone در entityهای syncable؛
- `created_by`, `updated_by` در mutationهای حساس.

جدول‌های کلیدی جدید:

`devices`

- `id`, `user_id`, `platform ANDROID|WINDOWS`, `name`, `app_version`؛
- `last_seen_at`, `revoked_at`؛
- public device metadata فقط؛ secret/token جدا.

`idempotency_records`

- tenant/user/key/operation unique؛
- request hash، response status/body hash، expiry؛
- mismatch همان key با payload دیگر -> conflict.

`outbox_events`

- envelope قرارداد مادر، state، attempt، available_at؛
- write با aggregate در همان transaction.

`job_records`

- `id`, `organization_id`, `workspace_id`, `type`؛
- `state QUEUED|RUNNING|RETRY_WAIT|COMPLETED|FAILED|CANCELLED`؛
- lease owner/expiry، attempt، max_attempts، idempotency key؛
- safe error fields.

`audit_records`

- actor/tenant/action/target/correlation/timestamp؛
- before/after فقط allowlisted/redacted fields؛
- append-only.

## 6. Sync Protocol v1

### 6.1 اصول

- local-first؛
- at-least-once transport + idempotent application؛
- cursor-based incremental pull؛
- mutation precondition و conflict آشکار؛
- tombstone؛
- blob جدا از metadata؛
- protocol version negotiation؛
- clock client برای ordering authority نیست؛ server sequence authority است.

### 6.2 Change log

`sync_changes`

- `sequence` monotonic bigint؛
- `organization_id`, `workspace_id`؛
- `entity_type`, `entity_id`, `entity_revision`؛
- `operation UPSERT|DELETE`؛
- `changed_fields` allowlisted یا canonical payload reference؛
- `occurred_at`, `actor_id`, `device_id`؛
- index `(workspace_id,sequence)`.

Cursor opaque و signed/versioned باشد؛ client نباید sequence tenant دیگر را query کند.

### 6.3 Push mutation envelope

```json
{
  "protocolVersion": 1,
  "deviceId": "uuid",
  "batchId": "uuid",
  "mutations": [
    {
      "mutationId": "uuid",
      "entityType": "task",
      "entityId": "uuid",
      "baseRevision": 4,
      "operation": "UPDATE",
      "patch": {},
      "clientOccurredAt": "RFC3339"
    }
  ]
}
```

Response per mutation `APPLIED|DUPLICATE|CONFLICT|REJECTED` + canonical revision. batch partial success صریح است؛ transaction boundary را مستند کن.

### 6.4 Conflict policy

| نوع | Policy |
| --- | --- |
| append-only event/revision | merge با ID dedupe |
| Task/Project/Person editable | base revision؛ conflict object، بدون silent LWW |
| Task state transition | server domain transition؛ stale -> conflict |
| Memory revision | append؛ current pointer conflict resolution صریح |
| Delete tombstone | entity unavailable؛ update stale reject مگر restore permission |
| Projection/read model | local rebuild، هرگز push نشود |
| Transcript/AI derived | server canonical؛ client annotation جدا |

`sync_conflicts` با local/server snapshot hash، state OPEN|RESOLVED و resolution audit ساخته شود. PII snapshot کامل در log ممنوع.

### 6.5 Endpoints

```text
POST /v1/sync/push
GET  /v1/sync/pull?workspaceId=&cursor=&limit=
GET  /v1/sync/snapshot-manifest?workspaceId=
POST /v1/sync/snapshot-requests
GET  /v1/sync/conflicts
POST /v1/sync/conflicts/:id/resolve
```

## 7. Audio/Object Storage

### 7.1 Blob schema

`blob_objects`

- `id`, tenant/workspace؛
- `purpose RAW_AUDIO|DERIVED_AUDIO|DOCUMENT|EXPORT`؛
- `storage_key` opaque؛
- `content_type`, `byte_length`, `sha256`؛
- `state PENDING|UPLOADING|AVAILABLE|QUARANTINED|DELETED`؛
- encryption/key version metadata؛
- retention/deletion timestamps؛
- UNIQUE tenant + sha + purpose طبق dedupe policy.

`upload_sessions`

- `id`, `blob_id`, `device_id`؛
- `part_size`, `part_count`, `expires_at`؛
- `state`, timestamps؛
- uploaded parts manifest/hash.

### 7.2 Workflow

```text
Local durable chunk
-> create upload session
-> resumable part upload via signed URL
-> server complete request
-> verify length/SHA/MIME
-> AVAILABLE
-> ASR job
-> Transcript/Understanding
```

Metadata Conversation می‌تواند قبل از blob sync شود ولی UI `AUDIO_PENDING_UPLOAD` را صادقانه نشان دهد. ASR قبل از AVAILABLE اجرا نشود. signed URL کوتاه‌عمر، tenant-bound و method/content-length محدود.

Raw audio retention configurable؛ delete account/workspace cascade job قابل ممیزی. Object orphan scanner و DB/object reconciliation gate اجباری.

## 8. AI Model Gateway و Usage

Providerها پشت Port:

- `TranscriptionProvider`؛
- `UnderstandingProvider`؛
- `EmbeddingProvider` فقط اگر واقعاً استفاده می‌شود؛
- `ModelPolicyResolver`؛
- `UsageRecorder`.

`model_catalog`

- internal model key، provider adapter، capability، region، enabled، policy metadata؛
- UI نام Provider خام را لازم نیست بداند.

`ai_executions`

- tenant/workspace/job/operation/model key؛
- input/output token/audio seconds، latency، status، provider request ID hashed؛
- prompt/schema version، cost estimate nullable؛
- content یا secret ذخیره نشود.

`usage_events`

- append-only، idempotency key؛
- metric `AUDIO_SECONDS|MODEL_INPUT_TOKENS|MODEL_OUTPUT_TOKENS|STORAGE_BYTES|ACTIVE_DEVICE`؛
- quantity integer، occurred_at؛
- billing هنوز enforce نمی‌کند ولی data قابل reconcile است.

Provider retry نباید job تکراری یا usage double-count بسازد.

## 16. Acceptance scenarios

1. Android offline: login قبلی معتبر، Conversation 10 دقیقه، app kill/restart، audio recovered، network return، resumable upload، یک Transcript/Conversation.
2. Same Task Android و Desktop همزمان edit -> conflict آشکار، هیچ silent loss.
3. mutation batch دوبار -> duplicate response و یک canonical change/usage.
4. upload part قطع/تکرار -> complete با SHA درست و یک blob.
5. tenant A هیچ ID/search/blob/task tenant B را نمی‌بیند؛ matrix کامل.
6. revoked device token refresh/sync نمی‌کند.
7. Cloud/AI outage -> local capture ادامه، job retry، UI degraded.
8. account export شامل canonical data و manifests؛ secret/internal key ندارد.
9. deletion request -> login/state policy، purge jobs، audit، blob cleanup.
10. push overdue task -> no PII payload، deep link authz.
11. v0.17 local import -> ID/provenance حفظ و restart-safe.

## 17. Performance/Load gates

روی fixture و environment ثبت‌شده:

- API read p95 زیر 400ms، mutation p95 زیر 600ms در beta target load؛
- sync pull page bounded و payload زیر limit تعریف‌شده؛
- 10k concurrent upload session simulation بدون duplicate complete؛
- worker lease recovery بعد crash؛
- 1M sync change query index plan؛
- Android startup/cache rendering budget و battery/network profile؛
- audio upload memory-bounded؛ کل فایل در RAM ممنوع.

عدد load target را در ADR با فرض کاربر beta ثبت کن؛ بدون environment ادعای production scale نکن.
