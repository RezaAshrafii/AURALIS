# پرامپت اجرایی AURALIS v0.17.0 — Domain Product Layer

## دستور به مدل اجرایی

قرارداد مادر و اسناد v0.15/v0.16 را کامل بخوان. baseline اجباری v0.16.0 با Memory کنترل‌شده و evidence معتبر است. هدف این نسخه سه محصول روی Core واحد است؛ ساخت سه fork، سه database یا سه capture pipeline شکست معماری محسوب می‌شود.

## 1. نتیجهٔ محصول

کاربر هنگام ساخت Workspace یک Product Profile انتخاب می‌کند و workflow/UI مناسب می‌گیرد:

```text
AURALIS CORE
├── Voice CRM
├── Personal Assistant
└── Meeting
```

دادهٔ Conversation/Task/Memory/Document مشترک و canonical است. هر محصول projection، vocabulary، policy و workflow خودش را دارد.

## 2. Scope

### داخل Scope

- Product Profile و capability registry؛
- Voice CRM: Customer Profile، Interaction، Follow-up، lightweight Pipeline؛
- Personal Assistant: Today/Promises/Follow-ups/Overdue؛
- Meeting: Agenda/Attendee/Minutes/Decision/Task/Follow-up؛
- template و extraction policy per product؛
- projection/rebuild؛
- product-specific dashboard/navigation/export؛
- data portability بین profileها بدون duplication.

### خارج از Scope

- Cloud/multi-tenant/team collaboration؛
- external CRM sync؛
- Calendar/Email messaging واقعی مگر adapter فقط contract-level و disabled؛
- mobile؛
- billing؛
- enterprise access control؛
- جداکردن Core به serviceهای شبکه‌ای.

## 3. اصل One Core, Multiple Products

ممنوع:

- `apps/crm-copy`, `apps/meeting-copy` با کپی Core؛
- `if (product === ...)` پراکنده در Core؛
- table جدا برای Transcript/Task/Memory هر محصول؛
- prompt واحد با صدها شرط؛
- تبدیل projection به source of truth.

الگوی اجباری:

```text
Core event
  -> Product Projection Handler
  -> Product Read Model
  -> Product Workflow Service
  -> Product UI Module
```

Product module از contractهای public Core استفاده می‌کند. Core هیچ import از CRM/Assistant/Meeting ندارد.

## 4. Capability registry

تعریف typed/versioned:

```text
ProductProfile = CORE | VOICE_CRM | PERSONAL_ASSISTANT | MEETING
Capability = customer_pipeline | promise_tracking | meeting_minutes | ...
```

`product_profiles`

- `workspace_id` PK؛
- `profile`؛
- `config_json` schema-validated؛
- `schema_version`؛
- `revision`, timestamps.

Registry باید route، navigation، extraction template، dashboard widget، export template و policy را compose کند. feature flag برای rollout است، نه authorization.

تغییر Profile نباید داده را حذف کند. projection مقصد rebuild و UI عوض می‌شود؛ canonical Core ثابت می‌ماند.

## 5. Schema 12 — Shared projection infrastructure

`projection_checkpoints`

- `projection_name`, `workspace_id` PK؛
- `last_event_id`, `last_occurred_at`, `projection_version`؛
- `state READY|REBUILDING|FAILED`؛
- `error_code`, `updated_at`.

`projection_failures`

- `id`, `projection_name`, `event_id`, `attempt`, `error_code`, timestamps؛
- dead-letter visibility.

هر projection idempotent و rebuildable از canonical Core است. write model product-specific فقط جایی مجاز است که واقعاً دادهٔ user-authored جدید دارد.

## 6. Voice CRM

### 6.1 Domain

از `people` استفاده کن؛ Customer یک role/projection است، Person موازی نساز.

`crm_accounts`

- `id`, `workspace_id`, `name`, `status ACTIVE|ARCHIVED`؛
- `owner_person_id` nullable؛
- `revision`, timestamps.

`crm_contacts`

- `person_id` PK/FK؛
- `account_id` nullable؛
- `lifecycle LEAD|PROSPECT|CUSTOMER|INACTIVE`؛
- `source`, `tags_json` validated؛
- `last_interaction_at`, `next_follow_up_at`؛
- `revision`.

`crm_interactions`

- `id`, `workspace_id`, `contact_person_id`؛
- `conversation_id` UNIQUE nullable؛
- `kind CALL|MEETING|NOTE`؛
- `outcome POSITIVE|NEUTRAL|NEGATIVE|UNKNOWN`؛ outcome AI فقط suggested؛
- `summary_insight_id` nullable؛
- timestamps.

`crm_opportunities`

- `id`, `workspace_id`, `account_id`, `primary_contact_person_id`؛
- `title`؛
- `stage NEW|QUALIFIED|PROPOSAL|NEGOTIATION|WON|LOST`؛
- `amount_minor`, `currency` nullable؛
- `expected_close_at` nullable؛
- `loss_reason` nullable؛
- `revision`, timestamps.

`crm_opportunity_events` append-only stage/value changes.

Follow-up باید از canonical `tasks` استفاده کند؛ `crm_followups` table موازی نساز. link table در صورت نیاز:

`crm_task_links(task_id PK, contact_person_id, opportunity_id nullable, purpose)`.

### 6.2 CRM workflow

```text
Customer Conversation
-> Interaction projection
-> validated summary/outcome candidates
-> contact timeline
-> follow-up Task suggestion
-> user confirmation
-> pipeline update
```

AI حق تغییر stage/value یا ارسال follow-up بدون user action ندارد.

### 6.3 CRM UI

- CRM Dashboard: overdue follow-ups، recent interactions، pipeline summary؛
- Contacts list/detail با Conversation/Task/Memory timeline؛
- Opportunity board/list با accessible alternative؛
- New Call از Contact؛
- evidence drawer برای outcome/follow-up؛
- CSV/JSON export با schema/version و PII warning.

## 7. Personal Assistant

### 7.1 Domain strategy

Assistant تا حد ممکن read model روی Task/Commitment/Memory است؛ entityهای تکراری نساز.

`assistant_views`

- saved view/config، نه data truth؛
- `id`, `workspace_id`, `name`, `query_json`, `sort_json`, `revision`.

`promise_links`

- `insight_id` PK (type COMMITMENT)؛
- `task_id` nullable؛
- `direction USER_PROMISED|OTHER_PROMISED|MUTUAL|UNKNOWN`؛
- `counterparty_person_id` nullable؛
- `follow_up_at` nullable.

`daily_brief_runs`

- `id`, `workspace_id`, `local_date`, `timezone`, `input_fingerprint`؛
- `state`, `summary_text`, `created_at`؛
- UNIQUE per input fingerprint؛
- brief derived/rebuildable است.

### 7.2 Assistant workflow

- Today: due/overdue Task، promise follow-up، recent unresolved question؛
- «چه قول‌هایی داده‌ام؟» از confirmed Commitment + promise link؛
- «چه چیزی را فراموش کرده‌ام؟» فقط از overdue/unresolved canonical records؛ مدل حق اختراع ندارد؛
- daily brief با exact links به records؛
- snooze/reschedule با task event و timezone صحیح؛
- هیچ notification خارجی تا v0.18.

### 7.3 Assistant UI

- Today؛
- Promises؛
- Follow-ups؛
- Memory highlights با transparency؛
- quick capture text/conversation؛
- Global Command actions؛
- هر ادعا لینک به Task/Conversation/Memory.

## 8. Meeting Product

### 8.1 Domain

Conversation با `kind=MEETING` canonical است.

`meeting_records`

- `conversation_id` PK/FK؛
- `project_id` nullable؛
- `title`, `agenda_text`؛
- `state PLANNED|LIVE|PROCESSING|READY|CANCELLED`؛
- `scheduled_start_at`, `scheduled_end_at`, `timezone` nullable؛
- `revision`.

`meeting_attendees`

- `conversation_id`, `person_id` PK؛
- `attendance INVITED|PRESENT|ABSENT|UNKNOWN`؛
- `speaker_channel_id` nullable؛
- `role_label`.

`meeting_minutes`

- `id`, `conversation_id`, `revision`؛
- `summary_text`, `prompt_version`, `input_fingerprint`؛
- `status DRAFT_AI|CONFIRMED|SUPERSEDED`؛
- timestamps؛
- evidence links برای sectionهای مهم.

Decision/Task/Commitment از canonical insight/task استفاده می‌کنند. linkهای view در صورت نیاز، duplicate row نه.

### 8.2 Meeting workflow

```text
Plan agenda/attendees
-> Start canonical Conversation
-> Audio/Transcript
-> Meeting extraction template
-> draft minutes + Decisions + Tasks + Commitments
-> human review
-> confirmed minutes/export/follow-up
```

### 8.3 Meeting UI

- planned/recent meeting dashboard؛
- agenda/attendee editor؛
- live view بدون false diarization claim؛
- post-meeting review queue؛
- Minutes editor با revision؛
- decisions/tasks/commitments filters؛
- Markdown/PDF-ready data export contract؛ PDF generation اگر baseline skill/tooling دارد و تست layout ممکن است، در غیر این صورت Markdown/JSON و `NOT_IMPLEMENTED` صریح.

## 9. Product-specific extraction

یک generic extraction port و سه template/schema version بساز:

- `crm-interaction-v1`؛
- `assistant-commitment-v1`؛
- `meeting-minutes-v1`.

همهٔ outputها به canonical Insight/Task/Memory candidate mapping می‌شوند. Product-specific field فقط در module خودش persist می‌شود. Evidence validation مشترک و غیرقابل bypass است.

Product profile، Conversation kind و user command template را انتخاب می‌کنند. متن transcript نمی‌تواند template/system prompt را انتخاب یا override کند.

## 11. Profile switching و Data portability

- user می‌تواند profile Workspace را عوض کند؛
- canonical Core data حفظ؛
- projection جدید async/rebuildable؛
- progress/error visible؛
- capability route disabled با 404/403 stable error، نه crash؛
- profile switch idempotent و rollbackable؛
- هیچ Memory حساس خودکار به CRM view expose نشود مگر policy اجازه دهد.

## 12. Migration

- schema 11 -> 12؛
- Workspaceهای موجود `CORE` profile بگیرند؛
- migration خودکار Person را CRM Contact نکند؛ user opt-in/import لازم؛
- Conversation kind MEETING موجود می‌تواند meeting candidate شود، نه confirmed meeting record بدون review؛
- Commitmentهای confirmed برای promise link backfill قابل review؛
- projection rebuild از event/canonical data و restart-safe.

## 13. Security/Privacy

- CRM export دارای PII policy و explicit user action؛
- amount/currency validation و no float؛
- Memory sensitivity filter در تمام product read modelها؛
- product profile authorization server-side؛
- no cross-workspace projection leakage؛
- evidence quote و prompt-injection protections مشترک؛
- audit برای stage change، minutes confirmation، profile switch و export.

## 14. Acceptance scenarios

### CRM

1. Person را با opt-in Contact کن؛
2. از Contact تماس شروع کن؛
3. Interaction با Conversation link؛
4. follow-up suggestion با evidence؛
5. confirm -> canonical Task؛
6. Task completion در Contact timeline و Action Center یکسان.

### Assistant

1. سه Task و دو Commitment در چند Project؛
2. Today فقط due/overdue صحیح timezone؛
3. «قول‌های من» direction صحیح؛
4. daily brief بدون hallucinated item و با link؛
5. snooze یک task event می‌سازد.

### Meeting

1. agenda/attendee؛
2. live Conversation واقعی؛
3. transcript + draft minutes؛
4. evidence-backed Decisions/Tasks/Commitments؛
5. human confirm؛
6. export revision درست.

### Cross-product

- یک Task در Core/CRM/Assistant/Meeting یک ID و state دارد؛
- profile switch data loss/duplication صفر؛
- projection rebuild خروجی deterministic؛
- product disabled route data افشا نمی‌کند؛
- Memory استفاده‌شده transparency دارد.

## 15. Performance و Reliability

- projection handler idempotent و retry/dead-letter؛
- rebuild 100k event progress/cancel/resume؛
- CRM contact timeline cursor pagination؛
- pipeline/today/meeting dashboard p95 local زیر 400ms روی fixture هدف؛
- projection failure capture/Conversation canonical write را block نکند؛
- product read model stale state را با `lastProjectedAt` نشان دهد.

## 16. Definition of Done

- schema 12 و migration pass؛
- Core هیچ import از product modules ندارد؛ dependency test enforce؛
- سه profile workflow کامل و بدون dead UI؛
- canonical Task/Memory/Conversation duplicate نشده؛
- profile switch/rebuild/retry evidence؛
- v0.16 Memory controls و v0.15 UX و v0.14 audio regression pass؛
- Cloud/Sync/Billing صریحاً non-capability؛
- artifact v0.17.0 + checksum.
